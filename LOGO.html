foxai LOGO

Self-contained, AI-readable implementation spec for the foxai logo. Read this file top-to-bottom and you have everything you need to redraw the mark in any stack: path data, color tokens, three variants, and copy-paste recipes for raw SVG, React, CSS, and Tailwind.

Brand: foxai  ·  Tagline: One key. Every model.  ·  Accent: Ember (#E2571F)  ·  Mark name: Trace

1. The mark — “Trace”

The foxai mark is a lowercase f whose crossbar trails off into a detached, filled dot. The metaphor is a request: the trunk is the spine, the bar is the call, and the dot is the endpoint it terminates at. The negative space between the bar and the trunk reads as the path the response takes back, but only on a second look — primary recognition is just “an f with a freckle.”

1.1 Path data (the entire mark)

viewBox:        0 0 64 64
stroke-width:   7.5
stroke-linecap: round
stroke-linejoin: round
fill (paths):   none
fill (dot):     var(--brand)

<path d="M23 55V22c0-7.2 5.8-13 13-13h2" />     <-- spine + top hook
<path d="M12.5 31h21" />                          <-- crossbar (the request)
<circle cx="49" cy="9" r="5.5" fill="var(--brand)" />  <-- endpoint (filled)

The viewBox is fixed at 0 0 64 64 for every variant — change the width/height attributes, never the viewBox. The 64-unit grid places stroke endpoints on integer (or half-integer) coordinates, which keeps the rendered glyph on subpixel grid lines at 16/24/32/48 px and stops it from going fuzzy on hidpi displays.

1.2 Sizing rules

  • ≥ 20 px: use the bare Mark (strokes only). Strokes render cleanly down to about 18 px before they start to bleed together.
  • ≤ 24 px: switch to Tile (opaque background + reversed mark). A 7.5-unit stroke on a 24-px raster is roughly 2.8 px wide; on white page chrome it disappears.
  • Wordmark pairings: lockup's mark height should be ≈ 1.7× the wordmark cap height. The component scales both together (see §2.3).
  • Never render below 12 px. If a surface forces it, use a flat glyph, not the mark.

2. Variants

2.1 Mark — the bare stroke

Use wherever the surrounding surface has enough contrast for an outlined mark (white cards, dark nav, the playground header). Strokes inherit color from var(--brand) by default — pass stroke="currentColor" in the SVG to inherit surrounding text instead.

2.2 Tile — opaque background, reversed mark

Use for favicons, app icons, anywhere the bare mark would dissolve. The tile is a rounded square (corner radius 14 on a 64-unit grid, ≈ 22% of the side) and the mark inside is recoloured to var(--brand-foreground) (white in light mode, near-black in dark mode).

2.3 Lockup — Mark + wordmark

The default for navbars, auth cards, and "powered by" placements. The mark inherits the foreground colour so it sits calmly next to text; the wordmark is set in 600-weight with a tightened tracking (-0.01em), and the letters ai lift to brand colour so the accent lands in the type, not just the glyph.

foxai foxai small size uses the mark at ~14–16 px and the wordmark at ~10–11 px

3. Color tokens

Three tokens, light + dark. Everything else (chart palette, focus rings, soft fills) is derived from --brand.

Light

--brand · #E2571F · oklch(0.633 0.185 39.6)
--brand-foreground · #FFFFFF · oklch(0.99 0 0)
--brand-muted · rgba(226, 87, 31, 0.12)

Dark

--brand · #FF7A4D · oklch(0.727 0.173 39)
--brand-foreground · #1A1A1A · oklch(0.16 0 0)
--brand-muted · rgba(255, 122, 77, 0.16)

The two Ember hues were chosen in OKLCH (not HSL) so the dark variant stays in the same perceived lightness class as the light variant — orange-on-white at 0.633 L flips to orange-on-black at 0.727 L and the saturation/chroma numbers barely move. Don't pick the dark variant by eye; the hue hovers at 39° in both modes.

4.2 React / JSX component

import type { SVGProps } from 'react'

// MARK_PATHS — the spine, the crossbar, and the endpoint.
const MARK_PATHS = (
  <g
    fill="none"
    stroke="var(--brand, #E2571F)"
    strokeWidth={7.5}
    strokeLinecap="round"
    strokeLinejoin="round"
  >
    <path d="M23 55V22c0-7.2 5.8-13 13-13h2" />
    <path d="M12.5 31h21" />
    <circle cx="49" cy="9" r="5.5" fill="var(--brand, #E2571F)" stroke="none" />
  </g>
)

type LogoProps = SVGProps<SVGSVGElement> & {
  size?: number
  title?: string
}

/** Bare stroke mark — for surfaces with enough contrast for an outline. */
export function Mark({ size = 24, title, ...rest }: LogoProps) {
  return (
    <svg width={size} height={size} viewBox="0 0 64 64"
         role={title ? 'img' : 'presentation'}
         aria-label={title} aria-hidden={title ? undefined : true}
         {...rest}>
      {title ? <title>{title}</title> : null}
      {MARK_PATHS}
    </svg>
  )
}

/** Opaque tile with reversed mark — for favicons, app icons, ≤ 24 px. */
export function Tile({ size = 24, title, ...rest }: LogoProps) {
  return (
    <svg width={size} height={size} viewBox="0 0 64 64"
         role={title ? 'img' : 'presentation'}
         aria-label={title} aria-hidden={title ? undefined : true}
         {...rest}>
      {title ? <title>{title}</title> : null}
      <rect width="64" height="64" rx="14" fill="var(--brand, #E2571F)" />
      {MARK_PATHS}
    </svg>
  )
}

/** Mark + "foxai" wordmark, where "ai" picks up the brand accent. */
export function Lockup({
  size = 24,
  title,
  className,
  ...rest
}: Omit<LogoProps, 'size'> & { size?: number }) {
  return (
    <span className={className}
          style={{ display: 'inline-flex', alignItems: 'center', gap: 8 }}>
      <Mark size={size} title={title} {...rest} />
      <span style={{
        fontWeight: 600,
        letterSpacing: '-0.01em',
        fontSize: Math.round(size * 0.6),
        lineHeight: 1,
      }}>
        fox<span style={{ color: 'var(--brand, #E2571F)' }}>ai</span>
      </span>
    </span>
  )
}

5. Usage rules

DOUse the lockup at navbar/auth-card sizes (16–32 px mark, 10–22 px wordmark).
DOUse the tile wherever the bare mark would disappear (favicons, OS-tray, anything ≤ 24 px).
DORecolour the endpoint dot together with the strokes; never the strokes alone.
DOKeep a clear-space of at least one cap-height around the mark on every side.
DON'TDon't recolour the strokes and the dot independently — they're one shape.
DON'TDon't outline the tile or drop-shadow the mark.
DON'TDon't rotate, skew, or stretch the viewBox.
DON'TDon't set the dot to a different colour from the strokes.

6. Design rationale (why it looks like this)

  • Lowercase f, not capital F. Lowercase feels like infrastructure, like a function call. Capital F feels like a nameplate; lowercase feels like a utility.
  • The crossbar that doesn't quite reach. The bar starts at x=12.5 (left of the spine at x=23) and stops at x=33.5 (right of the spine). The asymmetry — sticking out left, tucked in right — is what gives the mark direction. A symmetrical bar reads as a tic-tac-toe grid.
  • The detached endpoint. Most f-marks finish the bar with a serif or a curl. We replace that with a separated dot. This is the only filled shape in the mark and it's what carries the metaphor: a request leaves the bar, travels through empty space, and arrives at a node. Functionally, the dot is also what keeps the mark readable at 16 px — without it, the f looks like a t.
  • Stroke width 7.5 on a 64-unit grid. 7.5 is the largest stroke that doesn't visually crowd the crossbar or eat the hook. Below 6 and the mark feels thin; above 9 and the negative space between bar and spine closes.
  • Corner radius 14 on the tile. 14/64 = 0.22, which sits between iOS (≈ 0.22) and Material (≈ 0.125). It reads as friendly without looking rounded.
  • "ai" gets the brand colour, "fox" stays neutral. The accent is the suffix, the value-neutral part stays black. This is deliberate: it's the brand saying "the AI is the accent, the fox is the carrier."
